# 2026-10-25 — A blogroll page, also as OPML

- Date: 2026-10-25
- Status: Accepted
- Decided by: JC, asking for "a blog/website roll". The starting list is
  seeded from sites JC's own posts link to, for JC to trim and add to.

## Context

A blogroll is the IndieWeb's oldest way to point readers at the people
you read, and it's how independent sites find each other without a
platform in the middle. Feed readers import and export subscription
lists as OPML, so a blogroll that ships as OPML lets a reader follow
everyone on it in one step. Everything else on the site is Markdown in
`content/`, edited in Obsidian and readable on GitHub.

## Decision

- `content/blogroll.md` is an ordinary page at `/blogroll/`. Each list
  item is one site: `- [Name](https://site/) ([feed](https://site/feed.xml)): why I read it.`
- The build reads the rendered list and also writes `/blogroll.opml`
  (OPML 2.0): one `rss` outline per site with a feed, a `link` outline
  for one without. The page links it in `<head>` as
  `rel="alternate" type="text/x-opml"` and with a visible link under the
  list.
- Every page's footer links the blogroll, next to the feeds, when the
  page exists. The header nav stays Notes, About, Colophon.
- An item that doesn't start with a link to a site is a build error, so
  the OPML can't silently drop a site.

## Consequences

- One Markdown list is the only thing to edit; the page and the OPML
  can't drift apart.
- The list's syntax is a light convention (first link, a link reading
  "feed"). Free text, headings and an intro paragraph around the list
  are fine; nested lists are not.
- The OPML has no `dateCreated`/`dateModified`: the build has no clock in
  its output (spec/build-invariants.md), and feed readers don't need it.
- The build makes no network requests, so it doesn't check that the
  listed sites or feeds are up.

## Alternatives considered

- **Front-matter list of sites.** Structured, but YAML of URLs is
  harder to read and edit in Obsidian than a Markdown list, and the
  page would need its own template.
- **Page only, no OPML.** Simpler, but readers would add each feed by
  hand, which is the chore OPML exists to remove.
- **`rel="blogroll"` link** (a 2023 proposal from Dave Winer's
  Feedland). Not a registered link type, so the Nu HTML Checker CI job
  would reject it; `rel="alternate"` with the OPML type is valid today.
- **A header nav link.** The footer already holds the feeds, which is
  where a reader looking for things to subscribe to looks.
