# 2026-11-06 — Drop tags; notes relate through links

- Date: 2026-11-06
- Status: Accepted
- Decided by: JC, who asked when tags came in and whether they were needed,
  then chose "Drop tags" over keeping front-matter tags only
  or keeping them as they were.

## Context

No decision ever chose tags.
They came with the first scaffold on Quartz 4,
whose config turned on its tag pages and tag list
([383ad13](https://github.com/dijonkitchen/posse-bliki/commit/383ad13)).
The rebuild the same day kept them in `spec/content-schema.md`
([435adda](https://github.com/dijonkitchen/posse-bliki/commit/435adda)),
and the Rust build ported them
(ADR 2026-10-06-rust-build-zero-dependencies).

How they worked:
a note got tags from a `tags` front-matter list
or from any `#word` in its text outside code.
The build showed each as a `#tag` link (`p-category`) under the title,
wrote a `/tags/<tag>/` page listing those posts,
added it to the sitemap,
and put the tags in the JSON Feed.

How they were used:
5 of 68 notes, two tags.
`#podcast` grouped the 4 podcast episodes imported from Substack,
and `#meta` marked "How this bliki works".
None of the 46 Jekyll posts had tags.
No page linked to a tag page except those 5 notes,
and there was no index of tags.

The inline rule could also make a tag by accident.
It took any `#` followed by a lowercase letter or digit,
so "we're #1" would have built `/tags/1/`.
Obsidian, the editor this vault is written in,
doesn't count a tag made only of digits
([Obsidian Help: Tags](https://obsidian.md/help/tags)).

## Decision

- **No tags.**
  The `tags` field leaves the front-matter schema,
  so a note that has one fails the build like any unknown field
  (spec/content-schema.md).
  A note promoted from Obsidian drops it first.
- **A `#word` is text.**
  The build no longer turns it into a link.
- **Notes relate through links.**
  A link, with backlinks shown on the note it points to,
  says why two notes go together;
  a shared tag only says that they do.
  Andy Matuschak calls tags
  "quite a low-signal way of describing relationships"
  ([Tags are an ineffective association structure](https://notes.andymatuschak.org/Tags_are_an_ineffective_association_structure)),
  and suggests letting structure emerge from links
  ([Prefer associative ontologies to hierarchical taxonomies](https://notes.andymatuschak.org/Prefer_associative_ontologies_to_hierarchical_taxonomies)).
- **The old tag pages redirect.**
  `/tags/meta/` and `/tags/podcast/` were public and in the sitemap,
  and URLs are forever (spec/url-policy.md),
  so they get the same redirect page as `/all`
  (ADR 2026-10-16-old-all-page).
  `/tags/podcast/` goes to `/notes/`, which lists the episodes with every other post.
  `/tags/meta/` goes to `/colophon/`,
  which tells how the site works
  and took in "How this bliki works"
  (ADR 2026-11-06-how-this-bliki-works-split).
- Post pages lose `p-category`
  and JSON Feed items lose `tags`;
  both are optional
  ([h-entry](https://microformats.org/wiki/h-entry),
  [JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/)).
  RSS never had them.
- `tests/harness/no_tags.rs` checks a `#word` stays text,
  a `tags` field fails the build,
  and no page links to `/tags/`.
  `tests/harness/aliases.rs` checks the two redirects.

## Consequences

- Less to build, style and specify:
  the inline parser, the tag pages and the pill styles are gone.
- Writing `#` in a note is safe;
  it shows as typed.
- The 4 podcast episodes no longer share a page.
  If they need one, a note that links to each of them does that job,
  and says what the podcast was.
- Promoting an Obsidian note with `tags:` takes one more edit.

## Alternatives considered

- **Keep front-matter tags only.**
  Removes the accidental-tag trap,
  but keeps tag pages no page links to,
  for two tags.
- **Keep tags as they were.**
  Martin Fowler's bliki, where the word comes from,
  uses tags as its main way to browse
  ([bliki](https://martinfowler.com/bliki/)).
  That pays off across hundreds of posts on a few themes,
  not 68 notes and two tags.
  If browsing by topic is wanted later,
  it's a new ADR,
  and could start from hand-written index notes rather than tags.
